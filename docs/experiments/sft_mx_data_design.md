版本：2026-10-05。状态：数据设计已完成，题目可用性已做只读审计；演示采集、训练数据发布和 SFT 训练尚未执行。

工作区：`/mnt/public/code/lyk/lzy/R1-sft-mx`。分支：`sft-mx`，基于用户确认的 `data-difficulty-muxi`；创建前已提交全部当时未提交改动，基础提交 `28da7731b9f4b37bc5fa7007acfbac9101748876`。原工作区保留正在运行的检查点评价。

## 1. 训练目标与边界

从相同 Qwen2.5-7B Base 做少量、高质量的检索交互 SFT，优先教会模型：正确发起搜索、根据真实结果决定下一步、串联多跳证据、证据足够时输出答案并结束。主方案不从已出现严重重复的 step100 权重继续 SFT。

| 已发现的问题 | 数据需要提供的示范 | 能力与限制 |
| --- | --- | --- |
| 未闭合标签、无效动作、答案嵌在 think 中 | 每轮闭合 think，随后只有一个合法 search 或 answer 动作 | SFT 可建立正确协议的起点，效果待完整轨迹评价 |
| 重复搜索、无进展的长输出、证据充分后仍继续 | 有目的的改写查询、多跳推进、真实证据后的简短完整答案 | 不用单纯压短全部轨迹来抑制循环；保留必要多轮 |
| 模型自行生成 information，但最终答案仍获奖 | information 只来自真实检索；模型输出不得冒充工具结果 | SFT 可减少这类示例进入起点；后续 RL 的结果奖励仍可能强化错误过程 |
| 后期策略偏移、出现严重循环 | 分层覆盖正常完成的演示；SFT 后 reference 冻结为 SFT 起点 | 不能保证后续 100 周期稳定，需同预算 RL 对照 |
| 权重更新后的旧 KV 污染 | 新分支继承已验收的缓存失效修复，采集绑定实际权重版本 | 数据无法修复缓存 bug；旧训练内分数不作为验收依据 |

旧训练已开启 actor KL loss，系数 0.001。首轮 SFT 对照保持现有 RL KL、奖励及学习率配置，避免同时改变多项因素。若新增过程奖励，先离线审查并登记新版本，C2/C3 使用相同版本；不把修改奖励的收益归给 SFT。

## 2. 可用数据与隔离

已确认的源文件：

- 原训练集：`/mnt/public/code/lyk/lzy/data/datasets/nq_hotpotqa_train/train.parquet`。
- 官方测试集：同目录 `test.parquet`，隔离审计只读取 question 列。
- 已冻结 P/D/T：`/mnt/public/code/lyk/lzy/data/runs/formal-pdt-7b8-v1/manifest.json`，以及对应 P/D/T Parquet；P10000 为后续 RL 题池，整个 D1000 为开发集，T2000 封存。

本次只读审计校验原始 train/test 文件 SHA256 与既有 manifest 一致。原训练集 169,615 行，其中 NQ 79,168、HotpotQA 90,447。排除 P/D/T 问题哈希、所有官方测试问题并对剩余规范化文本去重后，候选为 **158,551 道**：NQ 73,982、HotpotQA 84,569。排除计数按处理顺序为 P/D/T 哈希匹配 11,010 行、官方测试重复 2 行、剩余重复 52 行。

此数量尚未经过 tokenizer 长度检查、近重复复核、教师成功率筛选和证据审查，不能写成合格演示数量。本次未读取封存 T.parquet，未读取官方测试答案，未调用 GPU。

隔离实现采用两层：

1. 永久 question_id 复用现有规则：SHA256(JSON `[source, "train", original_id, normalized_question]`)，JSON 编码与 `pool_preparation.py` 一致。排序种子可以单独带 sft-mx 命名空间，题目身份不能换命名空间绕过去重。
2. normalized_question 复用 NFKC、casefold、标点与空白规范化；同时匹配既有 manifest 的 question_hash，并排除所有官方 test 问题。先全局去重，再划分训练、验证与探针。

在生成前进行近重复候选筛查：词集合 Jaccard ≥0.80 或字符 5-gram 相似度 ≥0.85 的候选对送人工判断；这些阈值是待实现的筛查起点，不能作为已验证的语义去重结论。与 P/D/官方 test 以及 S_train/S_val 的近重复均检查，只读取问题，不依赖测试答案。共同引用 Wikipedia 文档不等于问答泄漏；不得人工向检索结果追加 gold 或演示。

## 3. 规模、选题顺序与行为覆盖

数量以不同问题计，每题最多保留一条完整轨迹。训练来源配额沿用现有比例。

| 阶段 | 问题预算 | NQ / HotpotQA | 用途 |
| --- | --- | --- | --- |
| 教师探针 | 固定尝试 64 题 | 30 / 34 | 测量合格率、缺陷和真实制作成本；不承诺 64 条合格轨迹 |
| S256 | 合格 256 题 | 120 / 136 | 一轮 SFT 先导；可包含同版本审核通过的探针题 |
| S1000 | 合格 1,000 题 | 467 / 533 | 正式起点；S256 嵌套于其中 |
| S_val | 合格 128 题 | 60 / 68 | 独立的逐 token 预测损失诊断，不进入 S_train |

建议先冻结训练候选 5,000 题（2,334 / 2,666），另冻结验证候选 512 题（239 / 273），均以 seed=42 的稳定哈希排序。训练候选的前 64 题按来源配额组成探针。每题最多 8 次模型采样；训练候选最多 40,000 次模型轨迹尝试是上限，不是计划全量消耗。具体调用预算在探针后结合实测检索成本登记。

每个来源先按问题 tokenizer 长度三分位分层，再生成固定候选顺序。按该顺序取审核合格题，达到来源配额后停止。无法达到目标时报告不足，不临时调低多跳来源比例、不反复抽到只剩容易题。记录原候选与接受集合的长度、轮数、查询数及合格率分布。

行为采用可重叠标签，作为覆盖审查，不设置拍脑袋的硬比例：

| 行为标签 | 示范要求 |
| --- | --- |
| single_search | 一次真实检索后得到足够依据，随后正确停止 |
| multi_hop | 从第一轮证据识别实体或关系，再查下一跳，最终连接证据 |
| query_refinement | 首次结果不支持答案；下一次查询确有改写目的并带来新证据 |
| stop_after_evidence | 当前可见信息已足够，下一轮给出完整答案，无冗余搜索 |
| direct_answer（可选） | 原提示允许无需外部知识时直接回答；必须独立人工核验，不声称有检索依据 |

不能仅按数据源把 NQ 视为单跳、HotpotQA 视为多跳。检索轮数由实际轨迹确定。探针后若多跳或改写示范明显缺失，应修订候选/教师方案并新建数据版本，再扩大；不靠复制同一条轨迹填充覆盖。零检索轨迹不用于填满主数据配额，首版可单独保留审查记录，是否并入在数据冻结前明确。

## 4. 教师与真实交互采集

主教师为未经过本次 RL 的同一 Base；采集和学生使用原 RL prompt、tokenizer 与有界上下文协议。先自生成并严格验证，探针结果不足再形成更强教师方案的新版本。训练过的 v4、其他 Instruct 教师、带答案的教师提示不能默默混入主方案。

采样 temperature/top_p 等值从既有训练协议展开配置中读取并冻结；为每题/attempt/turn 派生稳定 seed，最大 8 次不同采样。不能只记录全局 seed 或逐题答错后人工随意改提示。采用同一真实 retriever、同一索引/编码器、topk=3；固定最大 10 轮、每轮生成 256、观察上限 2048、总轨迹预算 4096，具体值须与启动时冻结配置核对。

当前 bounded 协议保留原问题和完整历史，并预留最终回答空间，预算不足会添加强制最终回答提示。SFT 主数据拒绝触发 forced_final 的轨迹，避免把预算耗尽才作答当成正常示范。max_start_length=256 不能被误用为截掉原问题的规则；真实首轮输入以 bounded 生成器实际发送的 token 为准。

新增采集能力应沿用实现计划中的可选 trace_sink，关闭时原生成行为保持一致。现有 checkpoint_eval 追踪可作参考，但它未暴露真实 finish_reason，也未覆盖全部后处理/观察边界，不能直接宣称可发布 SFT 数据。

每次真实模型调用记录：

- trajectory_id、question_id、attempt_id、turn_id、seed、权重及协议版本。
- 发送前的非 padding context_ids、attention/position 边界；GPU 补齐行不计真实样本。
- 原始生成 token/text，经过 `_postprocess_responses` 后实际保留的 assistant token/text，以及有效动作类型。
- 真实 search 查询、一次调用的返回 passages、原生文档 ID（若有）、分数及耗时；没有 ID 时使用索引版本与内容 SHA256，不能把 Doc 1 当永久文档 ID。
- 裁剪后真实可见的 observation_ids、原始/保留长度、裁剪标记；下一轮以真实 context_ids 为准。
- 真实引擎停止原因（若接口可接入）、是否命中生成长度、预算/轮数强制结束、是否完成答案。

记录工具结果复用同一次调用，不为审计再次查询并替换结果。检索超时、服务错误、加载错误单独登记 infrastructure_error；保留失败尝试，基础设施重试仍使用相同尝试身份并记录重试号，另设有限重试预算，不能无限重试或将错误伪装为空结果。

## 5. 接受与拒绝规则

一条轨迹只有全部检查通过才能发布。最终正确只是必要条件。

| 检查 | 接受条件 | 典型拒绝原因 |
| --- | --- | --- |
| 答案 | 共享 response_only_v1 判分为 1，并人工/证据审核通过 | 仅 reward=1，但证据不支持，或多部分标签存在歧义 |
| 动作格式 | 闭合 think 后恰好一个合法 search 或 answer；答案不在 think 内 | 嵌套答案、混合多个动作、空查询、未闭合标签 |
| 工具来源 | 每个 search 对应实际请求和返回；assistant 不含自行编造的 information | 未调用工具却生成检索结果，查询/返回身份无法对应 |
| 信息边界 | 查询只依赖当时可见问题和历史；最终依据在对应上下文中可见 | 将 gold、未来 observation、教师私有 few-shot 复制进输入 |
| 完成与预算 | 完整最终答案，未强制结束，所有轮次满足真实协议长度 | forced_final、缺答案、目标截断、异常长循环 |
| 查询进展 | 多次检索有新目的/证据；完全重复查询无必要理由则拒绝 | 同一个无效查询循环，泛化填充文本 |

由于原生 finish_reason 目前未暴露，初版采取保守规则：任何轮原始输出长度达到每轮上限，进入人工复核并默认不发布，直到能确认动作完整且没有隐藏截断。保存原始输出与保留输出，两者不能混为一谈；长度命中不能直接写成已确认的真实截断。

证据审核至少把最终答案映射到可见 passage 的具体 span。多跳题需记录各跳关系；只在最后文档中找到答案字符串不能证明链路正确。证据可能被观察裁剪去掉，不能用完整返回文档替代学生当时看见的内容。自动字符串匹配只是预筛，不作为全部正确性的证明。

每个候选采用固定 attempt 顺序的第一条审核合格完整轨迹；不按最长思考、最大搜索次数或八条中的奖励最大值挑选。全部失败仍保留原因、采样和成本。错误/循环输出留在审计数据中，不能作为普通正向交叉熵目标；首版不加入偏好训练。

探针阶段复核全部拟保留轨迹；正式数据至少按来源、问题长度、轮数和行为标签分层复核 10%，所有自动标记风险与改写查询轨迹额外复核。发现系统性伪造、泄漏或边界错误时暂停该版本并全量重审相关分层，不仅删除抽中坏例后直接发布。

## 6. 逐轮训练样本与损失

原始 JSONL 保存所有尝试和审核字段；最终 Parquet 仅保存审核通过的训练行。每行对应一次真实模型调用，不把整段交互重新套 chat template。

| 轮次示意 | 输入 context | 监督 target |
| --- | --- | --- |
| 第 1 轮 | 原问题与协议提示 | `<think>…</think><search>查询一</search>` |
| 第 2 轮 | 真实历史 + 工具返回一 | `<think>…</think><search>查询二</search>` |
| 第 3 轮 | 真实历史 + 工具返回二 | `<think>…</think><answer>最终答案</answer>` |

此表仅展示边界，省略号和占位结果不会进入训练。target 使用 RL 后处理后实际保留并重新分词的 assistant token；raw_response_ids 用于审计。独立拼接文本再 tokenize 可能改变连接处 token，不能据此猜测边界。

最少字段：

```text
sample_id, question_id, source, trajectory_id, attempt_id, turn_id
context_ids: list[int]              # 当前真实可见输入，无 padding
target_ids: list[int]               # 当前实际保留输出，无 padding
question_target_tokens: int         # N_q：整题全部 target 的有效 token 数
sample_weight: float                # M / (Q * N_q)
protocol_hash, tokenizer_hash, teacher_hash, review_version, trace_hash
```

`input_ids = context_ids + target_ids`。labels 在 context、历史 assistant、工具文本及 padding 处为 -100，当前 target 处为实际 token ID。损失使用 `logits[:, :-1]` 对 `labels[:, 1:]`；首个目标 token 和末个目标 token 均参与预测。attention_mask 来自真实长度，不能通过 token 等于 pad_id 判断，因为 pad/eos 可能相同。

不人为给搜索轮追加 EOS；完整答案轮保留真实后处理语义，也不凭猜测额外添加终止 token。target 中的思考应简短、支持当前动作，不人工补写长思维链。环境文本只作为输入，当前目标中的模型自写 information 则必须拒绝。

逐行检验 context+target ≤4096，空 target/越界/缺审核立即拒绝；不静默截断目标或历史。初版右侧动态 padding、关闭 packing/remove_padding。每题完整轨迹缺一轮则整题不发布，不能保留几个容易轮次后声称是一条完整演示。

问题均衡目标沿用既有实现计划：

```text
L = (1/Q) * sum_q [sum_(turn,target token) CE / N_q]
batch_loss = sum_(real rows,target tokens) [M/(Q*N_q) * CE] / B
```

Q 为不同题数，M 为展开行数，B 为本次真实全局样本数。逐行均匀采样时该公式对应按题的全部目标 token 平均，防止轮数多/输出长的题自动占更大权重。跨卡与梯度累积按照技术计划验证分母，不再额外按每轮或每卡 token 数归一化。

## 7. 发布产物与可追溯性

实际执行后，在用户指定的外部数据产物目录建立版本目录，以下是拟定结构，当前没有生成这些数据：

```text
sft-mx/<data_version>/
  candidates/                      # 固定问题顺序、来源配额、隔离清单
  attempts/                        # 全部尝试、真实检索、异常及成本 JSONL
  reviews/                         # 自动检查、人工审核、证据 span、拒绝原因
  prepared/train.parquet           # 审核通过的逐轮 SFT 行
  prepared/val.parquet             # 独立 S_val
  manifest.json                    # 数据/模型/协议/审核/统计与 SHA256
  COMPLETE.json                    # 所有验证成功后最后发布
```

manifest 绑定源文件/PDT manifest/官方 test 问题清单哈希、候选顺序、去重算法版本、teacher/tokenizer/prompt/源码版本、retriever 索引与编码器/topk、采样设置与 seed、预算、原始追踪和审核版本。记录候选题数、尝试数、通过题数 Q、展开样本数 M、每题 N_q、有效目标 token 总量、各来源及行为分布和失败成本。训练文件不携带 gold、完整检索原文或未来轮次供 Dataset 随意读取。

只有文件齐全、哈希核对、题目隔离、样本 mask、逐轮上下文和审核验收全部通过才写 COMPLETE。部分数据不能供训练。续跑必须绑定相同 teacher、数据、协议和审核规则；修改教师/采样/预算/过滤即新版本，旧尝试与成本保留。

## 8. 实施顺序与验收

1. **冻结问题清单**：实现可配置路径的 prepare；复用永久 ID/规范化，检查全量 P/D/官方 test、近重复和 S_train/S_val 隔离。输出分层候选与实际拒绝计数。当前仅完成源文件/数量审计。
2. **接入真实追踪**：可选 trace_sink 覆盖生成输入、后处理目标、检索返回、观察裁剪和结束状态；关闭时行为不变。CPU 验证活动 ID/GPU 补齐/未来信息边界；有限 GPU 联调验证真实事件，不模拟工具成功。
3. **执行 64 题教师探针**：每题最多 8 次，所有拟保留轨迹人工复核。报告来源、行为、长度、合格率、检索/生成耗时和各拒绝原因。若不足，先修订教师或数据版本。
4. **发布 S256 与独立验证数据**：冻结顺序取合格轨迹，逐轮转换与 mask 检查，源文件/审核/统计一致后发布；目标数量不足即失败，不自动缩减实验规模。
5. **补齐并验收 SFT 入口**：现有 SFTDataset 缺失、PEFT 顶层导入及 BF16 默认路径仍需按技术计划处理；FP16/FSDP、损失、导出和恢复独立验收后再用 S256 训练。初始一轮、lr=5e-6、global batch=32，数值为计划。
6. **开发评价与放大**：先 C0→C1 完整检索评价，再 C2/C3 相同 RL 配置的先导。25 周期只能判断早期方向；验证后期循环仍需覆盖 60/80/100 周期及对应完整保存节点。通过后扩大 S1000；最终方案锁定后统一评价 T2000。

CPU 数据验收需要覆盖：ID/文本/近重复隔离；同题不能跨 split；真实工具与模型来源区分；环境中含 answer 字符串不产生监督；首末目标、单 token 目标、pad=eos；多轮整题完整性；空/超长目标；尾批占位；按题加权与不同微批/分卡的损失和梯度一致；变更哈希/缺文件时拒绝恢复。代码函数及关键逻辑遵循仓库中文注释规范。

主评价同时报告完整检索 EM、合法过程正确率、无答案、强制结束、模型自写 information、重复查询、实际工具次数和成本。S_val 预测损失不能替代完整检索 EM。SFT 数据构造成本包括所有拒绝尝试；共享检索语料不作为免费采集成本。
