# R1 生成质量改进方案

日期：2026-10-12。状态：设计完成，尚未实施或验证收益。依据为 mx 当前源码、quality-v1 前四步日志及具体轨迹。设计保持 GRPO 框架。

## 1. 问题与证据边界

证据利用不可靠：模型看见真实检索文档，却未准确提取实体、关系、时间或否定信息；也可能声称“文档支持某答案”，实际文档没有该内容。代表轨迹 68e0cb9d3a3742e199418026c1aec3cd:8 的可见文档明确含 Aaron Eckhart in The Dark Knight，回答却为 Geoffrey Rush，并声称 Doc 2/3 支持。该例的检索已提供答案，问题发生在读取和回答阶段。

交互协议不可靠：模型没有稳定区分自身输出、真实工具返回和下一轮动作。出现复述完整提示、执行占位查询 query、缺少闭合标签、续写其他用户对话、偏离原问题。模型自写 information/answer 的未执行尾部已被程序隔离；这些尾部不是工具结果，也不进入当前训练消费文本。需要分别记录消费文本异常与未执行尾部浪费。

这些例子证实能力缺陷，不能单独证明训练引发或加剧退化。当前只有四步且题目变化。前四步5120条候选的接受答案EM为972/5120=18.98%，未作答677/5120=13.22%；训练批次质量成功495/1024=48.34%，未作答88/1024=8.59%，重度重复21/1024=2.05%，轻度63/1024=6.15%。两种正确指标口径不同，筛选后指标不能当作整体正确率。

## 2. 已有能力与缺口

- protocol.py::parse_action 保护明确代码/引用区域，并寻找首个闭合动作；普通正文复述提示中的完整 search 标签仍可被识别为动作。TraceLedger 已记录真实 call_id、可见文档与来源，来源校验应复用。
- reasoning.py::review_reasoning 检查引用文字/文档编号，事实支持、多跳推理仍为 unknown。文本出现、编号存在不等于事实受到支持；当前语义诊断没有可靠地用于奖励。
- reward.py、bounded_reward.py、repetition.py 已做来源门控、未作答/无效动作成本和重复门控。少量可恢复的格式错误后最终答对仍可能得到正奖励，不能声称所有非法轨迹都无正奖励。
- generation.py 后处理首动作边界，token_alignment.py 保留原采样token；工具观察和人工边界有独立损失掩码。已有对齐诊断中41428轮未出现采样/文本前缀失败，但这不证明全部实现无缺陷。
- vllm_rollout.py 当前设置 detokenize=False，未接入动作结束标签停止；直接加 stop 字符串需要先核对当前 MetaX vLLM 实现与采样校验。

## 3. 实施步骤与验收

### P0：先建立可比较的诊断

复用 TraceLedger，将每条记录关联到 run、step、候选轮次、question_id、trace_uid、最终是否保留；候选、保留训练、固定验证分别统计。审计文件 phase=train 不能单独证明轨迹已被选入参数更新。输出以下故障类型：检索未找到证据、模型未利用已见证据、引用不成立、协议不合法、提示复述、问题偏离、重复、未作答。

固定原D256用于不改参数的验证；从训练题池构建独立诊断集，含直接证据、多跳、干扰实体、否定/时间约束、检索不足和合法无需搜索题。采用开发/诊断集校准，保留测试集不参与调参。初始模型与可用检查点共用检索语料、预算、采样设置，按题配对比较。

关键指标：原始EM、接受答案EM、质量成功、协议有效率、未作答率、轻/重重复、已检索到证据题上的正确率、无依据引用率、查询/生成token成本、总耗时。固定验证的采样温度应注明；训练temperature=1的候选不能与确定性验证直接比较。

### P1：明确每轮动作与停止边界

目标流程：模型生成本轮分析及一个顶层 search/answer → 程序执行search并注入真实观察 → 模型继续；answer接受后终止。think中的标签引用不能成为顶层动作；工具返回不允许由模型声明。首轮提示预置think需纳入状态，不能强制模型再打开一个think。仍允许合法直接作答。

先增加结构诊断并离线回放现有成功/失败轨迹，再试行版本化状态解析。一般可恢复的格式错误给具体反馈并限定重试；明确提示复述、伪造角色或持续跑题单列为严重违规。不要仅因查询等于query或词汇重合就判错；结合动作位置、完整提示复述和协议状态判断。

原生停止试验：在可兼容路径上于 </search> 或 </answer> 后终止采样，保留完整闭合标签、原token IDs及logprobs；不以单个组成token替代多token标签。先验证当前MetaX后端的detokenize/stop兼容性与标签在引用/think中出现的行为。简单字符串停止误截断时，改用解析器感知的边界，或先采用规范化输出格式；不直接开启未经验证的严格语法约束。停止只能减少尾部和计算浪费，不能解决已执行动作内部的语义错误。

接入位置：protocol.py、generation.py、vllm_rollout.py；算法状态与GPU/Ray分离，通过显式配置接入。训练、评分和推理共用协议。

验收：CPU覆盖首轮预置think、标签跨token、引用/代码标签、嵌套和未闭合、answer后终止、检索故障、批次重排。真实后端验证token/logprob/mask对应、停止后闭合标签保留、正常轨迹不丢失。工具/反馈/人工内容不计算策略损失。比较未执行尾部token、非法调用、缺答案、正确率与耗时；不能仅凭文本更规整判成功。

### P2：用高质量演示补齐读取和交互能力

当前初始化为Qwen2.5-7B基础模型；少量监督微调（SFT）作为候选路线，训练后仍接GRPO。建议先试500–2000条经审核的完整题目轨迹，规模是起始试验值，不是已验证最优值。

演示必须来自真实检索，按每轮context→target展开。只使用本轮之前实际可见、已裁剪的结果；标准答案只用于审核，不进入学生上下文。只对该轮模型目标token计算交叉熵，历史、工具返回、反馈和padding掩码为零。复用已有数据/损失模块前检查可用性、移位和预算。

覆盖：一个搜索即可回答、看见文档后正确抽取、基于已知实体继续多跳搜索、修正误检索、读取否定与时间条件、过滤干扰实体、合法不搜索、证据不足时继续搜索、必要时承认不足。正常样例必须足够，不能让所有题都变成固定“先搜索”模板。

验收：初始模型、SFT模型先做同一固定验证，再比较各自接GRPO。正确率、协议和成本一起评价；同题泄漏或仅模仿长分析均不构成收益。SFT不是必需前提，也不保证优于纯RL。

### P3：先评估证据支持，再谨慎引入奖励

复用可见文档账本，用 call_id+doc_id 作为身份，避免多次搜索的Doc 1混淆。针对最终答案和明确“文档声称X”的陈述，检查被引文档是否存在、引用内容是否支持该陈述、是否与可见证据冲突。引用存在/字符串重合只做诊断，不能当语义支持。

第一阶段离线人工标注200–500条，独立语义判定器只返回支持/矛盾/证据不足，并附实际可见证据段；覆盖多跳、别名、时间、否定、干扰和截断。模型自写未执行tail、不可见原始文档、未来轮次检索都不得用于判定。无法确认归入证据不足，不能自动当错答。

评估判定器的精确率、召回率及正常正确样例误罚。候选验收目标：高置信违规精确率至少95%，正常正确样例误罚率不超过2%；这是提案阈值，需报告样本数与不确定性，不是已有结果。先只报指标，不立即把所有题变成强制引用任务。

校准通过后再增加有界语义成本。沿用最终正确性主奖励与当前总过程成本上限0.12；只有高置信严重来源/协议/重复违规取消正奖励，一般错误先小额软罚。无搜索的合法正确答案保持可得正奖；有搜索但证据未覆盖答案不能一律取消正奖。任务成功标签、组资格和GRPO优势必须使用同一门控版本。

必做离线重放：严重违规奖励不为正、成功/失败混合组中严重违规不获正优势、全失败组不因小成本差异入选、奖励/标签/筛选不漂移。语法受约束采样如引入，需要复核rollout与训练概率口径，避免将约束后概率与原分布概率直接混用。

### P4：独立对照，逐项决定是否采用

固定起始权重、检索、题池、seed、G8、学习率和预算，先做短试验，再决定是否扩至100步。分组：A当前方案；B仅协议/原生停止；C仅SFT后沿用当前GRPO；D将验证有效的B/C结合；E在D上增加已校准的证据奖励。保存SFT单独效果，避免把SFT初始提升归于RL。比较相同更新步数，也比较相同墙钟或生成token预算；动态筛选会改变成本及题分布。

固定D256只能用于开发验证，不能从候选集挑题后宣称泛化。对同题做配对统计，报告置信区间；对正常直接作答、检索不足和多跳分别汇报。接受标准为协议和证据利用改善，同时原EM没有可确认退步，搜索/token成本没有明显恶化。具体幅度根据基线方差预先登记。

## 4. 目前交付与限制

已完成代码/轨迹核对与方案设计。本次未修改训练源码、参数、采样或奖励，未启动新训练、停止现有任务或运行验收测试；以上均为待实现、待验证项。实现优先级：P0诊断 → P1最小协议试验 → P2小规模SFT对照 → P3语义校准及奖励 → P4扩大验证。不能把新增惩罚作为唯一解决方案。

## 5. 参考依据

- [Search-R1](https://arxiv.org/abs/2503.09516)：多轮真实检索、检索token掩码与结果奖励。支持继续使用GRPO/RL检索框架；不证明本项目必须SFT。
- [ReAct](https://arxiv.org/abs/2210.03629)：交替生成推理与动作、从外部环境获得观察。
- [ALCE](https://aclanthology.org/2023.emnlp-main.398/)：将答案正确性与引用质量分别评价。这里的语义奖励方案是结合本项目提出的设计。
- [vLLM SamplingParams](https://docs.vllm.ai/en/v0.10.2/api/vllm/sampling_params.html)：停止字符串与detokenize、保留停止字符串的参数语义。mx使用定制0.11.0，实施前必须核对本机版本并真实联调。
