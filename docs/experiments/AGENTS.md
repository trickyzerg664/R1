# 实验文档维护规则

继承仓库根目录 AGENTS.md。

- `grpo_difficulty_plan.md` 维护研究设计；`data_difficulty_steps.md` 维护执行顺序；`data_difficulty_progress.md` 是当前进度及交接的统一入口。
- 单次实验记录放在 `runs/<run_id>.md`，由 `runs/TEMPLATE.md` 创建。未启动的实验只登记计划，不伪造 run_id、时间、命令或结果。
- 每个阶段更新必须附证据位置、检查时间、负责人或 agent 标识、下一步及验收条件。不能确认的状态写“未核实”。
- 总台账只汇总状态并链接详细记录，实测数值和运行历史维护在对应运行记录中；设计改变要说明哪些运行受影响、是否仍可比较。
- 文档可入库；模型、原始数据、轨迹、大日志及未提交代码快照放在运行产物目录，通过路径和哈希关联。不要把凭据或环境秘密写入文档。

- 每次代码修改或实验执行后必须同步文档，失败和未验证的修改也要登记。代码变更同步实现记录与总台账；实验执行同步单次运行记录与总台账；方案、配置或执行方式改变时同步相应说明。
- 本次未重跑测试时，只能引用此前测试结果并注明适用范围；不能将历史通过结果写成本次新增代码已验证。

## 注释验收记录

- 新增或修改代码执行根目录 AGENTS.md 的中文注释规范：函数必须具备 `@brief`、各显式参数的 `@param`、`@return` 以及适用的异常/约束说明，关键逻辑必须就近注释。
- 实现记录必须列出本次代码变更的逻辑单元清单、有效中文说明覆盖数/总数和计算结果，覆盖率至少 50%；全部函数与关键逻辑还须分别完整验收。
- 仅更新文档时，代码注释覆盖率记为“不适用”，说明未进行源码注释补齐或代码测试；保留历史审查数值及当时要求，不能改写为按新规则验收通过。
